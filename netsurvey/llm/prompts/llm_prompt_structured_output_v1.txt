*   **`moonid_associations` Logic (Strictly apply using ONLY extracted SITE_SPECIFIC_MOONID_DATA):**
    *   **Rule A (IP-Based - Confidence 1.0):**
        *   SVI IP Match: SVI IP (primary IP if multiple are configured on the SVI) falls within MOONID's `ip_range_definition`. Prioritize most specific. `resolution_method: 'SVI_IP_Match'`.
        *   ARP IP Match: ARP IP falls within MOONID's `ip_range_definition`. Same specificity. `resolution_method: 'ARP_IP_Match'`.
        *   Route Destination IP Match (Apply Route Specificity and Prefix Length Filter): `destination_prefix` matches MOONID's `ip_range_definition`. **CRITICAL FILTER:** An association via this method should ONLY be made if the route's `destination_prefix` on the switch is **more specific than or equal to a /20 prefix length for IPv4 (e.g., /20, /21, ..., /32) or more specific than or equal to a /48 prefix length for IPv6 (e.g., /48, /56, ..., /128).** Do NOT associate based on routes with prefixes broader than these thresholds (e.g., IPv4 /19, /16, /8, /0 or IPv6 /47, /32). Furthermore, even if the prefix length condition is met, an association via a route should generally be avoided if there is a more direct SVI or ARP-based association for the switch to *any* MOONID that is encompassed by or related to the route's destination. If a switch has a specific SVI in MOONID 'X', do not also associate it with MOONID 'Y' just because MOONID 'Y' has an IP range that is reachable via an allowed-prefix-length route on the switch. Flag route-based associations, especially if they are the sole basis for linking to a MOONID or if the MOONID itself defines a very large range. `resolution_method: 'Route_Destination_IP_Match'`.
    *   **Rule B (VLAN ID Match - Confidence 0.7 - ONLY if NO Rule A match for a MOONID):**
        *   Switch VLAN ID (from the filtered `vlans` list) matches MOONID's `vlan_id`. `resolution_method: 'VLAN_ID_Match'`.
        *   Further qualify: Only associate via VLAN ID if the switch has active, operational interfaces assigned to this VLAN (beyond just default port membership for an unused VLAN). Do not associate based on a VLAN ID that is defined in the MOONID data but appears unused or merely 'defined' on the switch without active participation in site traffic.
        *   **Specific Handling for VLAN 1 (applies IF the `vlan_id` for potential Rule B match IS 1):**
            *   If the MOONID being considered has `vlan_id: 1` AND an `ip_range_definition` (i.e., it's an L3 MOONID also mapped to VLAN 1):
                *   A Rule B association for this MOONID (via VLAN 1) should ONLY be made if there is Layer 3 evidence of this MOONID's `ip_range_definition` on the switch. This evidence includes:
                    *   IP addresses from the MOONID's `ip_range_definition` appearing in the switch's ARP table (`arp_entries`).
                    *   OR, a specific IP route (`routes`) on the switch whose `destination_prefix` matches or is part of the MOONID's `ip_range_definition` (this route must also satisfy the general route specificity filters, e.g., more specific than /20 for IPv4 or /48 for IPv6).
                *   If such L3 evidence is ABSENT, do NOT make this Rule B association for VLAN 1 to this L3 MOONID, even if the switch has VLAN 1 configured (and in the `vlans` list) and the MOONID data lists `vlan_id: 1`.
            *   If the MOONID being considered has `vlan_id: 1` but NO `ip_range_definition` (i.e., it's an L2-only MOONID defined for VLAN 1), then a Rule B association based on VLAN 1 matching should NOT be made.
            *   **General VLAN 1 Caution:** For any Rule B association, if the `vlan_id` involved is 1, exercise extreme caution. Only proceed with an association if the conditions for an L3 MOONID on VLAN 1 (as described above, requiring L3 evidence) are met. Avoid associating based on VLAN 1 for purely L2 MOONIDs or if L3 evidence is missing for L3 MOONIDs on VLAN 1.

If a switch's VLAN is associated with a MOONID primarily defined for a different site/building (as per MOONID data's own location fields, if available), this should be flagged for review even if a VLAN ID matches.
